  Curating your per-agent user-behavior memory (um_note/um_read) — when to
  save, update, consolidate, or delete learned behaviors, and keeping the
  AGENT MEMORY index healthy. Applies to any master agent with um_ tools.

## When to save (um_note)

- The user has shown the SAME behavior twice or more (one occurrence is an
  anecdote, not a pattern).
- It will change how you act next time (a standing constraint, a phrasing
  convention, a recurring correction) — not a fact about the world
  (mem_save) or a task to do (todo_add).

## Hygiene

- **Update, don't duplicate**: scan your AGENT MEMORY index first; if a
  note covers the same ground, um_note with the SAME name rewrites it —
  fold the new evidence in.
- **Consolidate near the cap**: at ~25+ notes, um_read the overlapping
  ones, merge them into one broader note, then delete the leftovers. The
  30-note cap exists to keep the index scannable.
- **Delete what proved wrong**: a behavior the user explicitly contradicts
  gets deleted or rewritten immediately — a stale "always X" is worse
  than no note.
- Summaries carry the whole point (they're all future-you sees each
  session); the body is for evidence and exceptions.

## Boundaries

- Never store secrets, credentials, or sensitive personal details.
- Your memory is yours: other agents keep their own; don't write notes
  about how OTHER agents should behave.

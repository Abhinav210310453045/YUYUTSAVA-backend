name: thinking
description: |
  First-principles decomposition of a vague or tangled idea. Use when the
  user's input is rough, ambiguous, or too big to act on — before any
  designing, building, or researching happens.
---

## When to use

- The card holds a one-liner like "app for X?" or "fix our onboarding".
- The user's message mixes several problems, or the goal hides an assumption.
- You feel the urge to write a long answer — that urge means the input needs
  sharpening first.

## Pattern

1. Restate the idea in ONE sentence — the sharpest version you can defend.
2. List the assumptions the idea silently makes (2-4, no more).
3. Find the load-bearing question: the one whose answer changes everything.
   Ask it with tr_ask_user (offer 2-3 concrete options when possible).
4. With the answer, split the idea into first-principles parts: what is truly
   fixed (constraints), what is chosen (decisions), what is unknown (risks).
5. Persist the sharpened statement + decomposition as ONE note
   (todo_add_note), and retitle the card if the sharper phrasing deserves it
   (todo_update).

## Gotchas

- Never answer the original vague form — sharpen, confirm, then move.
- One note per pass; don't spray five fragmentary notes on the card.

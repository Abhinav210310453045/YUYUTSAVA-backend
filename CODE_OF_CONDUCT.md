# Code of Conduct

## The short version

Be decent to people. Assume good faith. Argue about the code, not the person
who wrote it.

## What is expected

- **Focus on the work.** Critique designs, decisions and code. Do not make it
  about the individual.
- **Assume competence and good intent.** Someone who did something differently
  than you would have usually had a reason. Ask before concluding otherwise.
- **Be direct and be kind.** These are compatible. "This has a race condition
  in the reconnect path" is direct and kind. "Did you even think about this?"
  is neither.
- **Accept that maintainer time is finite.** This is a single-maintainer alpha
  project. Issues and PRs may sit. Pinging politely is fine; entitlement is not.
- **Respect a decision once it is made.** You can disagree, say so once, and
  move on. Re-litigating a settled decision across threads is disruptive.

## What is not acceptable

- Harassment, insults, or personal attacks.
- Demeaning comments about anyone's identity — including race, gender, gender
  identity, sexual orientation, disability, age, appearance, body size,
  ethnicity, nationality, religion, or level of experience.
- Sexualised language or imagery, and unwelcome sexual attention.
- Publishing others' private information without permission.
- Sustained disruption of discussions.
- Deliberately submitting malicious code, or using an issue thread to attack a
  contributor.

This applies in issues, pull requests, commit messages, code comments, and
anywhere else someone is representing the project.

## Enforcement

Report a problem privately through GitHub — open a
[private security advisory](https://github.com/Abhinav210310453045/YUYUTSAVA-backend/security/advisories/new)
if you need a confidential channel and have no other way to reach the
maintainer. Reports are handled privately and the reporter's identity is not
shared with the person reported.

The maintainer may, at their discretion: ask for a correction, edit or remove
the offending content, or block the account from the repository. Severity and
repetition govern which.

If the maintainer is the problem, saying so publicly in an issue is legitimate.

## Scope and attribution

This document is written for this project rather than adopted from a template.
If you are looking for a standard, widely-adopted alternative, the
[Contributor Covenant](https://www.contributor-covenant.org/) is the usual
choice and this project would accept a PR switching to it.

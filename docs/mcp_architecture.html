2. Boot sequence

daemon/main.py
   ├─ load .env
   ├─ Store.start()
   ├─ PermissionsPolicy.from_file()
   ├─ MCPClientManager()                          # owns all sessions
   ├─ MCPConfig.from_file()                       # ~/.yuyutsava/mcp_config.json
   ├─ mcp_manager.start(mcp_cfg)
   │    └─ for each server → asyncio.create_task(_run_server)
   │         ├─ stdio_client(StdioServerParameters(...))   ← spawn process
   │         │  or sse_client(url)                         ← open SSE
   │         ├─ ClientSession(read, write).initialize()
   │         ├─ session.list_tools()  → cap at spec.max_tools
   │         ├─ adapt(session, name, tool) for each        ← StructuredTool wrappers
   │         └─ park on stop_event (same task owns AsyncExitStack)
   ├─ build subagents — each gets mcp_manager
   ├─ build orchestrator — also gets mcp_manager
   └─ on SIGHUP → mcp_manager.hot_reload(new_cfg)  (diff add/remove/changed)

4. Config schema (drop into ~/.yuyutsava/mcp_config.json)

{
  "mcpServers": {
    "deepface":   { "command": "python",
                    "args": ["-m", "yuyutsava.mcp_servers.deepface.server"] },
    "filesystem": { "command": "npx",
                    "args": ["-y", "@modelcontextprotocol/server-filesystem", "~/Documents"] },
    "spotify":    { "url": "http://localhost:8765/mcp" }           ← remote SSE
  },
  "scopes": {
    "orchestrator":   ["spotify"],
    "file-organizer": ["filesystem"],
    "face-watcher":   ["deepface"]
  },
  "default_scope": []
}

After editing, send kill -HUP <daemon-pid> → MCPClientManager.hot_reload runs the diff (stop removed/changed, start added/changed) — no daemon restart needed.

5. Internal vs remote — what's actually supported

Internal / local stdio

Set command + args + env. The manager calls stdio_client(StdioServerParameters) which spawns a child process and pipes JSON-RPC over its stdin/stdout. The shipped deepface server (built with FastMCP) is the in-tree example.

Remote (SSE only)

Set url. The manager uses sse_client(url). No auth headers, no OAuth, no streamable-http — only public/loopback SSE works today. To add auth you'd need to wrap sse_client or thread httpx headers in loader.py:_run_server.

6. Is there a "YUYUTSAVA MCP client"?

No custom client was written. The MCP client is the official mcp.ClientSession from the Python SDK (vendored via pyproject.toml). Our code provides three things on top:

  • MCPClientManager — multi-server lifecycle (start / hot-reload / stop) with one asyncio task per server so anyio cancel scopes close in the same task that opened them.
  • tool_adapter.adapt() — wraps each MCP tool as a LangChain StructuredTool with namespaced name and content-flattening.
  • Scopes — the scopes map in config decides which servers' tools each agent sees, with default_scope as fallback. Implemented in tools_for().

7. Sampling and Elicitation — current status

Sampling

NOT handled. ClientSession() is constructed in loader.py:177 with no sampling_callback. SDK default returns ErrorData(INVALID_REQUEST, "Sampling not supported"), and initialize() does not advertise the sampling capability — so MCP servers won't even try.

Elicitation

NOT handled. Same picture: no elicitation_callback passed in; SDK default rejects with "Elicitation not supported" and capability isn't advertised. The daemon already has a ChannelRouter.ask() path (HITL prompts) that could be plumbed in if we ever want to support it.
